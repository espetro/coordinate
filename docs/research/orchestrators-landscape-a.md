# Orchestrators landscape, part A: how 12 open source orchestrators actually orchestrate

Date: 2026-11-22 (ran `date`). Scope: the 12 open source rows of `assets/orchestrators-landscape-2026-11.png`. Method: shallow clone of each repo's default branch on 2026-11-22, reading source and in-repo docs, `gh api` for stars, license and latest release, `gh issue list` for adversarial evidence. No agent was run, no model quota spent.
Evidence tags (as in `orchestrator-framing.md`): M = measured by us, R = read in the project's own source or docs, B = blog or marketing claim, K = from memory, unverified. Links to source point at the default branch as of 2026-11-22.

## 2. Comparison table: how each one orchestrates

"Concurrency" is the default cap and what happens to surplus. "kill -9" is what survives the orchestrator dying. Footprint is unknown unless stated; only Herdr was measured.

| Product | Process model | Concurrency | Durability and resume | Multi-device | Store | Footprint |
|---|---|---|---|---|---|---|
| Multica | Go daemon per machine spawns CLI per task (stdio, ACP for many runtimes, Codex app-server) | 20 tasks per daemon, 6 per agent, serialized per (issue, agent); surplus stays `queued` in Postgres | Task rows in server DB with prepare lease and stale sweeper; resume via `PriorSessionID` per issue | Central server, daemons pull over WebSocket wake + 30s poll | Postgres (pgvector) on server, files on daemon | Unknown |
| OpenHands SDK | Python agent server, ACP subprocess per conversation or built-in agent, optional Docker | `max_concurrent_runs` 10, surplus rejected with HTTP 429 | Files per conversation, lazy hydration, idle eviction keeps record, 45s file lease with generation fence | Canvas switches between several agent servers, each standalone | Files (`base_state.json`, events) | Unknown |
| Paperclip | Node server, one finite process per "heartbeat run" (CLI exits each turn) | `maxConcurrentRuns` 20 per agent, wakeups coalesced and queued in DB | Everything in DB, startup reaps orphans and resumes queue, `--resume <sessionId>` | Optional Rust "Paperclip Runner" process, SSH and sandbox leases | Embedded Postgres (no `DATABASE_URL`) | Unknown |
| OpenClaw | Node "Gateway" daemon, built-in agent loop, ACP harnesses via `acpx` plugin | Lane FIFO: `main` = max(8, CPUs*4), subagents 8 per session, swarm 32, bounded aging priority | Sessions and transcripts in per-agent SQLite, in-process queue, ACP `resumeSessionId` | Paired "nodes" over WebSocket, opt-in session hosting on nodes | SQLite per agent plus JSONL archives | Unknown, RSS growth issues open |
| Herdr | Single Rust binary, own PTY server, agents are unmodified TUIs | None | Layout snapshot in `session.json`, agent reports resume command via integration hook | One server per machine, client attaches over SSH | JSON files | 22MB idle RSS, 0.0% CPU, no panes (M) |
| Paseo | Node daemon, Claude Agent SDK, Codex app-server, ACP (Copilot), OpenCode | No agent cap found | JSON files, idle runtime released after 1h, resume on next prompt; restart resume opt-in, best effort | Daemon-to-daemon "connected hosts", optional E2EE relay | JSON files (atomic rename) | Unknown, OOM issue open |
| Paradev | Electron app, `host-service` plus detached `pty-daemon` owning PTYs | Unknown | PTYs survive app quit and upgrades (fd handoff), not "quit completely" or reboot; scrollback in memory | Host service on remote machine via Paradev Relay (pro) | SQLite (better-sqlite3) locally, Postgres and Redis for cloud | Unknown |
| Orchestrator (AO) | Go daemon, native PTY host for TUI mode, detached per-session host for ACP and Codex chat | No session cap found | SQLite durable facts, status derived at read time, detached hosts survive daemon replacement, hibernation of idle chat | Self-hosted remote VM via Cloudflare tunnel, sessions stay on their machine | SQLite | Unknown |
| CloudCLI | Node server, Claude Agent SDK and Codex SDK in process, node-pty for shells | Unknown | SQLite session rows with provider resume id; live run registry in memory | Single server, browser clients | SQLite plus provider JSONL | Unknown |
| QM | Node "core", Pi agent loop, per-scope durable sandbox | Run queue with claims, pg-boss | Postgres item log (WAL), run claim is the only turn lock and fences writes | Hosted core, sandboxes on Docker, E2B, Modal and others | Postgres (required) | Unknown |
| OpenChamber | Node server proxies one managed `opencode serve` | None of its own (OpenCode's) | Server-side message queue and goal loop; sessions owned by OpenCode | Desktop, web, mobile clients to one server, E2EE relay | Files plus OpenCode's store | Unknown, OOM issues open |
| Emdash | Electron desktop coordinates, "workspace host" executes; node-pty and ACP conversations | Unknown | Host-durable queued prompt payload until dispatch, session generation fence, tombstone deletion | Hosts over SSH, one supervisor per host connection | SQLite (better-sqlite3) | Unknown |

## 3. Per-product notes

### Multica

- Process model (R): `multica daemon start` "detects available AI CLIs on your machine, registers them with the Multica server, and executes tasks" ([CLI_AND_DAEMON.md](https://github.com/multica-ai/multica/blob/main/CLI_AND_DAEMON.md)). ACP-family runtimes (Hermes, Kimi, Kiro, Grok, MiniMax Code and others) are driven over ACP, Codex over its app-server (`thread/start`, `thread/resume`), others through their own protocols (same doc).
- Claim loop (R): "The server pushes a wake signal over the WebSocket connection when work is waiting, and the daemon claims across all of its runtimes in one batch. A periodic poll (default: 30s) runs as the catch-up path." Heartbeat every 15s (same doc). Claim SQL `ClaimAgentTask` sets `status='dispatched'` and `prepare_lease_expires_at = now() + prepare_lease_secs`, and "a task is only claimable when no other task for the same issue AND same agent is already dispatched or running" ([agent.sql](https://github.com/multica-ai/multica/blob/main/server/pkg/db/queries/agent.sql)).
- Concurrency (R): daemon `--max-concurrent-tasks` default 20 ([config.go](https://github.com/multica-ai/multica/blob/main/server/internal/daemon/config.go)); per-agent `max_concurrent_tasks` default raised from 1 to 6 ([migration 023](https://github.com/multica-ai/multica/blob/main/server/migrations/023_agent_concurrency_default.up.sql)). Surplus stays `queued` server-side.
- Durability (R): queue is server Postgres; daemon is stateless apart from workdirs. Resume is per issue: the daemon passes `PriorSessionID`, and drops it when the cwd or transcript is missing ([daemon.go](https://github.com/multica-ai/multica/blob/main/server/internal/daemon/daemon.go)). Boot autostart is opt-in via launchd or systemd; without it "every reboot takes the runtime offline and queued runs sit unclaimed" ([CLI_AND_DAEMON.md](https://github.com/multica-ai/multica/blob/main/CLI_AND_DAEMON.md)).
- Retention (R): GC with TTLs for artifacts, worktrees, bare repo cache, Hermes session store 14 days (`MULTICA_GC_HERMES_SESSION_TTL`) (same doc).
- Shared context (R): issues and comments are the shared context; Hermes memory is per agent and "Concurrent tasks of one agent are last-writer-wins" (same doc).
- HITL (R): agents "raise blockers" and hand back for review via issue status ([README](https://github.com/multica-ai/multica/blob/main/README.md)).
- Storage (R): self-host compose runs `pgvector/pgvector:pg17` plus backend, collab and web images ([docker-compose.selfhost.yml](https://github.com/multica-ai/multica/blob/main/docker-compose.selfhost.yml)). Fails G1 as a whole; the daemon alone is a Go binary.
- Adversarial (R): [#11039](https://github.com/multica-ai/multica/issues/11039) daemon "hangs in three distinct scenarios ... and never self-recovers"; [#5630](https://github.com/multica-ai/multica/issues/5630) daemon restart cancels active tasks instead of draining; [#10081](https://github.com/multica-ai/multica/issues/10081) lost resumed ACP session after reconnect not detected; [#6879](https://github.com/multica-ai/multica/issues/6879) cancelled checkout leaves an unrecoverable worktree.
- Modules: M2 (strong multi-protocol dispatcher), M4 (server queue, per-key serialization), M3 server-side. Not adoptable as a library (Go, server-coupled, license conditions). Copy: per-(issue, agent) claim serialization, prepare lease, WS wake plus slow poll catch-up, per-kind GC TTLs, "defer daemon self-restart until running tasks finish".

### OpenHands (Agent Canvas + software-agent-sdk agent server)

- Process model (R): Canvas is a UI; the agent server "spawns the agent's own CLI as a subprocess and relays each turn to it" over ACP JSON-RPC on stdio, or runs the built-in OpenHands agent ([ACP_AGENTS.md](https://github.com/OpenHands/OpenHands/blob/main/docs/ACP_AGENTS.md)). Runtime can be local, Docker, VM or OpenHands Cloud ([README](https://github.com/OpenHands/OpenHands/blob/main/README.md)).
- Concurrency (R): `max_concurrent_runs` default 10, "When full, create and run requests are rejected with HTTP 429" ([config.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/config.py)). An `asyncio.Semaphore` plus thread pool ([conversation_service.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/conversation_service.py)). No queue: surplus is the caller's problem.
- Park and wake (R): "Startup loads only lightweight metadata. An EventService and its event history are hydrated when a conversation needs a live runtime", and an idle-eviction loop "Evict[s] idle conversations, keeping the record so they re-hydrate on access", skipping running or subscribed ones (same file, `conversation_idle_ttl_seconds`). This is the parked/live split from our framing, implemented.
- Ownership lease (R): `owner_lease.json` per conversation, TTL 45s, `generation` counter, takeover flag, host and pid for crash detection, guarded by `filelock` ([conversation_lease.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/conversation_lease.py)). This is exactly a device-local lease with fencing.
- HITL (R): conversation states include `PAUSED` and `WAITING_FOR_CONFIRMATION` ([state.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/state.py)).
- Storage (R): file-based stores for settings and secrets ([persistence/store.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/persistence/store.py)), conversations as files with a disk-budget reclaimer and trash ([storage/reclaimer.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/storage/reclaimer.py)). Without `secret_key` "sensitive data is redacted, meaning full state cannot be restored between restarts" ([config.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-agent-server/openhands/agent_server/config.py)).
- Multi-device (R): Canvas "can connect to one or more Agent Server instances and switch between them" ([architecture.md](https://github.com/OpenHands/OpenHands/blob/main/docs/architecture.md)); no placement across servers.
- Adversarial (R): [SDK #5074](https://github.com/OpenHands/software-agent-sdk/issues/5074) TaskTool child keeps running and task mapping is lost after agent server restart; [SDK #7058](https://github.com/OpenHands/software-agent-sdk/issues/7058) coordinator run lost when a restart interrupts it; [SDK #6990](https://github.com/OpenHands/software-agent-sdk/issues/6990) sub-agent index lost across resume; [SDK #4810](https://github.com/OpenHands/software-agent-sdk/issues/4810) confirmation policy not persisted; [#19927](https://github.com/OpenHands/OpenHands/issues/19927) conversation interrupted by unexpected restart. Subagent state is the weak spot.
- Modules: M2 (ACP dispatcher with lazy hydration), M3 (file store with reclaimer). Python, MIT, could be run as a per-device dispatcher service, but RSS unknown and it brings its own agent stack. Copy: lazy hydration plus idle eviction, file lease with generation and pid/start-time crash detection, 429 vs queue decision (we want queue).

### Paperclip

- Process model (R): "Paperclip does not keep an agent process alive between turns. A heartbeat run is finite: it starts, performs work, records a terminal result, and exits. If work must continue later, Paperclip represents that intent in database state and creates another heartbeat run" ([durable-continuation-scheduler.md](https://github.com/paperclipai/paperclip/blob/master/doc/architecture/durable-continuation-scheduler.md)). Local adapters `claude_local`, `codex_local` resume with `--resume <sessionId>` from persisted runtime state ([agent-runs.md](https://github.com/paperclipai/paperclip/blob/master/doc/spec/agent-runs.md)). A Rust "Paperclip Runner" process owns provider sessions outside the server for some adapters ([paperclip-runner.md](https://github.com/paperclipai/paperclip/blob/master/doc/architecture/paperclip-runner.md)).
- Wakeups (R): a single "Wakeup Coordinator" for `timer`, `assignment`, `on_demand`, `automation`, with dedupe and coalescing, claims queued wakeups and creates `heartbeat_runs` ([agent-runs.md](https://github.com/paperclipai/paperclip/blob/master/doc/spec/agent-runs.md)). Scheduler tick default 30s, minimum 10s; startup reaps orphaned runs, promotes due retries, resumes queued work, then reconciles "stranded" issues ([durable-continuation-scheduler.md](https://github.com/paperclipai/paperclip/blob/master/doc/architecture/durable-continuation-scheduler.md)).
- Concurrency (R): per-agent `maxConcurrentRuns`, default `AGENT_DEFAULT_MAX_CONCURRENT_RUNS = 20` ([constants.ts](https://github.com/paperclipai/paperclip/blob/master/packages/shared/src/constants.ts)); admission rechecks "company scope, invokability, budgets, concurrency, and task ownership" ([AGENT-LIFECYCLE.md](https://github.com/paperclipai/paperclip/blob/master/doc/AGENT-LIFECYCLE.md)). Budgets in cents per month exist (same doc), the only one of the 12 with spend budgets in admission.
- Awaits (R): durable records for "pending interactions, approvals, monitors, blockers, and execution stages", continuation kinds `same_agent`, `retry`, `delegated_issue`, `response_wake`, `monitor` ([durable-continuation-scheduler.md](https://github.com/paperclipai/paperclip/blob/master/doc/architecture/durable-continuation-scheduler.md)). Locks: issue execution lock, workspace and environment leases (dozens of `*-lease*.ts` services in [server/src/services](https://github.com/paperclipai/paperclip/tree/master/server/src/services)).
- Storage (R): embedded PostgreSQL started automatically into `~/.paperclip/instances/default/db/` when `DATABASE_URL` is unset ([DATABASE.md](https://github.com/paperclipai/paperclip/blob/master/doc/DATABASE.md)). Fails G1 in spirit (a Postgres server process, even if managed).
- Adversarial (R): [#13631](https://github.com/paperclipai/paperclip/issues/13631) recovery backstop ends a live run, "agent stuck running, wakeup stuck claimed, result and usage lost"; [#14752](https://github.com/paperclipai/paperclip/issues/14752) status stays running after orphan terminalization, wedging agents with `maxConcurrentRuns: 1`; [#11978](https://github.com/paperclipai/paperclip/issues/11978) timeout not fired when process detaches; [#9555](https://github.com/paperclipai/paperclip/issues/9555) pool leak causes restart loop under launchd KeepAlive; [#958](https://github.com/paperclipai/paperclip/issues/958) memory leak from unpaginated heartbeat runs. The reconcile-everything approach generates many edge cases.
- Modules: M4 and M5 design reference (wakeup coordinator, continuation kinds, budgets). Not adoptable (embedded Postgres, very large server). Copy: "finite run, durable intent" model, coalesced wakeup table, typed continuation kinds, budget as an admission check.

### OpenClaw

- Process model (R): a long-running Node "Gateway" with a built-in agent runtime (`src/agents/embedded-agent-runner/`), plugin harnesses (Codex app-server) selected per model/provider ([agent-runtime-architecture.md](https://github.com/openclaw/openclaw/blob/main/docs/agent-runtime-architecture.md)). External harnesses (Claude Code, Gemini CLI, OpenCode) through the `@openclaw/acpx` ACP backend plugin ([tools/acp-agents.md](https://github.com/openclaw/openclaw/blob/main/docs/tools/acp-agents.md)). It is a personal assistant gateway for chat channels first, coding orchestration second.
- Concurrency (R): "a lane-aware FIFO queue drains each lane with a configurable concurrency cap"; `main` lane = max(8, CPU parallelism x 4) via `agents.defaults.maxConcurrent`, subagents 8 per spawning session, swarm collectors 32 per group; priority with bounded head start (foreground up to 15s, background up to 30s) then aging ([concepts/queue.md](https://github.com/openclaw/openclaw/blob/main/docs/concepts/queue.md)). A per-session "controller mailbox" grants one turn per physical session before global capacity (same doc). Queue modes `steer`, `followup`, `collect`, `interrupt` with 500ms debounce and cap 20 (same doc).
- Durability (R): it is "a tiny in-process queue" (same doc); inbound messages "can be persisted before their turn enters the mailbox" for durable-ingress channels. Session rows and transcripts in `~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite` ([concepts/session.md](https://github.com/openclaw/openclaw/blob/main/docs/concepts/session.md)). ACP children resume with `resumeSessionId` (ACP `session/load`), documented as the way to "pick up work that was interrupted by a gateway restart" ([tools/acp-agents](https://github.com/openclaw/openclaw/tree/main/docs/tools/acp-agents)). `interrupt` cancellation "does not resume the old turn through Gateway restart recovery" ([queue.md](https://github.com/openclaw/openclaw/blob/main/docs/concepts/queue.md)).
- Multi-device (R): "nodes" pair with the Gateway over WebSocket, are "peripherals, not gateways", and can opt into hosting sessions with `nodeHost.workerRuns.enabled` ([nodes/index.md](https://github.com/openclaw/openclaw/blob/main/docs/nodes/index.md), [nodes/session-hosting.md](https://github.com/openclaw/openclaw/blob/main/docs/nodes/session-hosting.md)). Central gateway, so a node loses its scheduler when the gateway is down (unknown how hosted runs behave then).
- Shared context (R): memory subsystem with builtin, Honcho and search backends and provenance ([docs/concepts](https://github.com/openclaw/openclaw/tree/main/docs/concepts), `memory-*.md`). Subagent completion ownership across `sessions_yield` is defined ([subagent-yield-handoff.md](https://github.com/openclaw/openclaw/blob/main/docs/concepts/subagent-yield-handoff.md)).
- HITL (R): exec approvals ([tools/exec-approvals.md](https://github.com/openclaw/openclaw/blob/main/docs/tools/exec-approvals.md)).
- Adversarial (R): [#182369](https://github.com/openclaw/openclaw/issues/182369) Gateway RSS grows about 0.1 GiB per hour off-heap until restart; [#140443](https://github.com/openclaw/openclaw/issues/140443) recurring RSS growth and OOM restart cycle on macOS; [#162709](https://github.com/openclaw/openclaw/issues/162709) transcript workers never retire, about 23MB/min; [#198187](https://github.com/openclaw/openclaw/issues/198187) workers exhaust heap after 1.5 days. Fails G2 in practice on a 200-300MB budget.
- Modules: M4 design reference (lanes, per-session mailbox, bounded-aging priority), M2 via acpx. Not adoptable (monolith, memory growth). Copy: lane plus capacity group model, one-turn-per-session mailbox ahead of global capacity, priority with bounded head start (aging) which answers our S9, `steer/followup/collect/interrupt` vocabulary for messages to a busy session.

### Herdr

- Process model (R): one Rust binary; a background server owns PTYs and "doesn't wrap or replace" agents, it "owns their terminals" ([README](https://github.com/herdrdev/herdr/blob/master/README.md)). Not tmux; it can run inside tmux but does not inspect tmux sessions in a pane ([agents.mdx](https://github.com/herdrdev/herdr/blob/master/docs/next/website/src/content/docs/agents.mdx)).
- State detection (R): per-agent TOML manifests with regex rules over screen regions (OSC title, bottom lines) mapping to `working`, `blocked`, `idle` ([src/detect/manifests/claude.toml](https://github.com/herdrdev/herdr/blob/master/src/detect/manifests/claude.toml)); remote manifest updates from herdr.dev applied without restart ([agents.mdx](https://github.com/herdrdev/herdr/blob/master/docs/next/website/src/content/docs/agents.mdx)). `herdr agent wait <target> --until STATUS --timeout MS` blocks until another agent is in a state ([cli-reference.mdx](https://github.com/herdrdev/herdr/blob/master/docs/next/website/src/content/docs/cli-reference.mdx)).
- Durability (R): `session.json` and `session-history.json` snapshot of layout ([src/persist/io.rs](https://github.com/herdrdev/herdr/blob/master/src/persist/io.rs)); after a server restart an agent "that also reports its resume command comes back in the same session" via `herdr integration install <name>` ([agents.mdx](https://github.com/herdrdev/herdr/blob/master/docs/next/website/src/content/docs/agents.mdx)). Resume identity includes the directory because `agent --continue` means different sessions in different cwds ([src/agent_resume.rs](https://github.com/herdrdev/herdr/blob/master/src/agent_resume.rs)).
- Multi-device (R): "Each machine keeps its own Herdr server, sessions, and running processes. A lost connection to one machine does not disconnect the others", over SSH with `ControlPersist 600` ([connecting-machines.mdx](https://github.com/herdrdev/herdr/blob/master/docs/next/website/src/content/docs/connecting-machines.mdx)). This is our per-device local-first topology.
- Concurrency, locks, shared context, rate limits: none found (R, absence in docs and CLI reference).
- Footprint (M): v0.9.5 `herdr server` on macOS arm64 with an isolated HOME and no panes: 22,000 KB RSS, 0.0% CPU after 16s, 0.39s CPU time. Per-pane cost not measured.
- Adversarial (R): [#5921](https://github.com/herdrdev/herdr/issues/5921) OpenCode panes restore to a new chat after a cold restart; [#4205](https://github.com/herdrdev/herdr/issues/4205) remote attach restart prompt misreports; screen-scraping manifests must chase every TUI release (the Claude manifest comments on spinner glyph changes by CLI version, [claude.toml](https://github.com/herdrdev/herdr/blob/master/src/detect/manifests/claude.toml)).
- Modules: M2 tmux-fallback replacement candidate (PTY server with CLI and socket API), M1 partial (SSH per machine). Small enough to adopt as the TUI fallback dispatcher. Copy: manifest-driven state detection with `explain`, resume command reported by the agent, per-machine independent servers.

### Paseo

- Process model (R): Node daemon "spawns and manages agent processes"; Claude via Agent SDK, Codex via app-server, Copilot via ACP, OpenCode, Pi ([docs/architecture.md](https://github.com/getpaseo/paseo/blob/main/docs/architecture.md)).
- Park and wake (R): "Idle resumable runtimes are collected after one hour without activity, checked once a minute. Collection releases the process and preserves the agent record, conversation, relationships, and provider session. The next prompt resumes that session" ([docs/agent-lifecycle.md](https://github.com/getpaseo/paseo/blob/main/docs/agent-lifecycle.md)). `closed` is "the persisted, resumable state for an agent record that has no live provider runtime" ([architecture.md](https://github.com/getpaseo/paseo/blob/main/docs/architecture.md)).
- Restart (R): "Restart recovery is off by default", `agents.resumeOnStartup` reopens saved conversations and sends `Resume working.`; "best-effort continuation. A crash between saving intent and dispatching a prompt can lose or repeat a continuation" ([architecture.md](https://github.com/getpaseo/paseo/blob/main/docs/architecture.md)).
- Agent-to-agent (R): one ordered delivery queue per recipient daemon; senders choose `queue` (default, 2s quiet window, 10s max), `steer` or `interrupt`; Stop holds, does not drop, queued messages ([agent-lifecycle.md](https://github.com/getpaseo/paseo/blob/main/docs/agent-lifecycle.md)).
- Concurrency (R, by absence): no agent concurrency cap found in `packages/server/src` (grep for `maxConcurrent`, `concurrencyLimit` hits only git command metrics).
- Storage (R): "file-based JSON persistence instead of a traditional database", atomic temp-and-rename, under `$PASEO_HOME` ([docs/data-model.md](https://github.com/getpaseo/paseo/blob/main/docs/data-model.md)).
- Multi-device (R): a daemon can register other daemons as "connected hosts", credentials in `hosts.json` mode 0600, one physical link per registration ([docs/connected-hosts.md](https://github.com/getpaseo/paseo/blob/main/docs/connected-hosts.md)); optional E2EE relay.
- Adversarial (R): [#6522](https://github.com/getpaseo/paseo/issues/6522) daemon worker crash-loops on V8 heap OOM with a long OpenCode session (unbounded in-memory timeline); [#8696](https://github.com/getpaseo/paseo/issues/8696) restart recovery intent lost during graceful shutdown; [#6477](https://github.com/getpaseo/paseo/issues/6477) renderer keeps every timeline in memory.
- Modules: M2 (multi-provider), M3 (JSON stores), M5 (agent messaging queue), M1 (daemon-to-daemon hosts). Copy: idle collection with "next prompt resumes", per-recipient ordered queue with queue/steer/interrupt and Stop-holds semantics, daemon-to-daemon host registry.

### Paradev

- Process model (R): Electron app plus `host-service` (tRPC) plus a detached `@superset/pty-daemon` that owns PTYs over a Unix socket; daemon "outlives host-service crashes via detached spawn + manifest adoption", and phase 2 fd handoff lets sessions survive a daemon binary swap with the same shell PIDs ([pty-daemon/README.md](https://github.com/ParadevAI/Paradev/blob/main/packages/pty-daemon/README.md), [DAEMON_SUPERVISION.md](https://github.com/ParadevAI/Paradev/blob/main/packages/host-service/DAEMON_SUPERVISION.md)).
- Durability (R): agents keep running after window close, Cmd-Q and updates, but "Quit Paradev Completely: No. All terminal sessions end" ([keep-agents-running.mdx](https://github.com/ParadevAI/Paradev/blob/main/apps/docs/content/docs/keep-agents-running.mdx)); scrollback "Buffer is in-memory only" ([pty-daemon/README.md](https://github.com/ParadevAI/Paradev/blob/main/packages/pty-daemon/README.md)). Reboot resume is an open feature request ([#3496](https://github.com/ParadevAI/Paradev/issues/3496), [#7806](https://github.com/ParadevAI/Paradev/issues/7806)).
- Storage (R): `better-sqlite3` and drizzle in host-service ([package.json](https://github.com/ParadevAI/Paradev/blob/main/packages/host-service/package.json)); cloud side uses Postgres 17 and Redis 7 ([docker-compose.yml](https://github.com/ParadevAI/Paradev/blob/main/docker-compose.yml)).
- Multi-device (R): a remote machine runs `paradev start --daemon`, reached through Paradev Relay, `pro: true` ([remote-access.mdx](https://github.com/ParadevAI/Paradev/blob/main/apps/docs/content/docs/remote-access.mdx)).
- Concurrency, locks, shared context: unknown (not found in docs read).
- Adversarial (R): [#6700](https://github.com/ParadevAI/Paradev/issues/6700) resource digest misses host-service's own RSS; [#5921](https://github.com/ParadevAI/Paradev/issues/5921) renderer at about 107% CPU after days of uptime.
- Modules: M2 PTY layer only. Copy: detached PTY daemon with manifest adoption and fd handoff across upgrades (the cleanest answer to "orchestrator restart must not kill agents").

### Orchestrator (Orchestrator.inc, `ao`)

- Process model (R): "a long-running Go daemon"; TUI sessions run in "a native PTY/ConPTY runtime, with tmux as a legacy or fallback runtime"; "Codex and all ACP Chat processes run in detached per-session hosts, so replacing the daemon or desktop app does not stop an in-flight turn. The ACP host also preserves connection setup, JSON-RPC correlation, pending interactions, and acknowledged prompt replay while the replacement daemon rebuilds its typed controller" ([docs/architecture.md](https://github.com/OrchestratorInc/agent-orchestrator/blob/main/docs/architecture.md)).
- State model (R): "Display status is never stored. It is computed at read time from durable facts"; durable facts are `activity_state` (`active`, `idle`, `waiting_input`, `blocked`, `exited`), `hibernated_at`, `is_terminated`, session mode plus controller generation, PR facts (same doc).
- Hibernation (R): a Chat provider host is stopped after a settled idle turn when no view is open, only if "the native conversation supports resume and no transition or pending work exists"; it is not hibernated while waiting for input, during unconfirmed turns or while a short view lease is held; wake on open, send or relay. Gated behind Developer Mode (same doc). This is the most careful park rule in the set.
- Handoff (R): durable TUI-to-Chat handoff of a native conversation, both controllers never live at once (same doc).
- Storage (R): SQLite with a `change_log` CDC table ([architecture.md, Persistence and CDC](https://github.com/OrchestratorInc/agent-orchestrator/blob/main/docs/architecture.md)).
- Multi-device (R): "Sessions stay on the machine that started them. Desktop and mobile are clients"; self-hosted remote VM via Cloudflare tunnel, AO account sign-in required ([docs/self-hosted-remote.md](https://github.com/OrchestratorInc/agent-orchestrator/blob/main/docs/self-hosted-remote.md)).
- Concurrency (R, by absence): no session cap found in `backend` (grep hits only terminal and version refresh semaphores).
- Adversarial (R): [#5948](https://github.com/OrchestratorInc/agent-orchestrator/issues/5948) reviewer outlives daemon restart as an orphaned pty-host and agent with PPID 1 while the session is terminated, the cost of detached hosts; [#8770](https://github.com/OrchestratorInc/agent-orchestrator/issues/8770) Stay Awake turns itself off after restart.
- Modules: M2 (best reference for ACP dispatch that survives orchestrator restart), M3 (facts vs derived status), M4 partial (hibernation). Go, Apache-2.0, but app-sized. Copy: detached per-session ACP host with prompt replay, hibernation eligibility table, derived status, controller generation fence.

### CloudCLI (claudecodeui)

- Process model (R): Node server with `@anthropic-ai/claude-agent-sdk` and `@openai/codex-sdk` in process, `node-pty` for shells ([package.json](https://github.com/siteboon/claudecodeui/blob/main/package.json)); resume by passing the provider session id as `sdkOptions.resume` ([claude-runtime.provider.ts](https://github.com/siteboon/claudecodeui/blob/main/server/modules/providers/list/claude/claude-runtime.provider.ts)).
- Durability (R): sessions table holds cwd and "provider-native resume id"; a finished run stays addressable for `COMPLETED_RUN_RETENTION_MS` 5 minutes in an in-memory registry ([01-websocket-transport.md](https://github.com/siteboon/claudecodeui/blob/main/docs/architecture/01-websocket-transport.md)). The SDKs run inside the server process (R, package.json). What happens to an in-flight run when that process dies is not documented: unknown.
- Concurrency, locks, multi-device placement: unknown; a scheduled-messages module exists ([server/modules/scheduled-messages](https://github.com/siteboon/claudecodeui/tree/main/server/modules/scheduled-messages)).
- Adversarial (R): [#1270](https://github.com/siteboon/claudecodeui/issues/1270) outgoing messages silently discarded when the WebSocket is closed, "no queue"; [#1452](https://github.com/siteboon/claudecodeui/issues/1452) first prompt silently lost; [#1002](https://github.com/siteboon/claudecodeui/issues/1002) session permanently lost due to a JSONL indexing bug.
- License: AGPL-3.0, fine for internal use, flag for anything distributed.
- Modules: control panel only. Nothing to adopt. Lesson: with the SDK in process, agent and orchestrator share one process; whether a run survives a server restart is not documented.

### QM

- Process model (R): central "core" (API, identity, policy, scheduler) plus Pi agent loop plus a per-scope durable sandbox reached via one `execute` tool ([README](https://github.com/yc-software/qm/blob/main/README.md)).
- Durability (R): "durable execution against a central write-ahead log: the session's item log, stored in the `items` table. To execute an agent turn, a worker claims a queued run from the run queue; that run claim is the session's only turn lock and fences the turn's writes" ([docs/SPEC.md](https://github.com/yc-software/qm/blob/main/docs/SPEC.md)). pg-boss and `FOR UPDATE SKIP LOCKED` claims with `claim_expires_at` (same doc).
- Delegation and awaits (R): persistent subagent sessions; a request key makes `subagents.open` idempotent after a lost receipt; finished children wake the parent; "Completion receipts are acknowledged only after durable inbox insertion and any required completion wake succeed", and a sweep retries pending returns after restart ([persistent-subagent-sessions.md](https://github.com/yc-software/qm/blob/main/docs/persistent-subagent-sessions.md)). Peer wakes stop after eight in a row ([SPEC.md](https://github.com/yc-software/qm/blob/main/docs/SPEC.md)).
- Storage (R): "Core requires Postgres" ([README](https://github.com/yc-software/qm/blob/main/README.md)). Fails G1.
- Self-critique (R): SPEC.md keeps a log of over-engineering it removed, for example invented swarm maximums removed in [qm#2141](https://github.com/yc-software/qm/pull/2141) and idle workers issuing about 64 claim UPDATEs per second fixed in [qm#1255](https://github.com/yc-software/qm/pull/1255) ([SPEC.md](https://github.com/yc-software/qm/blob/main/docs/SPEC.md)).
- Adversarial (R): [#2182](https://github.com/yc-software/qm/issues/2182) local sandbox stuck forever after its Docker network is removed while parked; [#1680](https://github.com/yc-software/qm/issues/1680) memory notebook PUT has no revision check, captures silently lost.
- Modules: M4 and M5 design reference only (wrong harness model, Postgres). Copy: run claim as the only turn lock with write fencing, idempotent request keys for spawn, completion receipt acked after durable inbox insert, peer-wake loop limit.

### OpenChamber

- Process model (R): web server that manages one OpenCode process and proxies it; "OpenCode process state survives HMR ... so a reload cannot orphan a managed child" ([packages/web/server/DOCUMENTATION.md](https://github.com/openchamber/openchamber/blob/main/packages/web/server/DOCUMENTATION.md)). OpenCode only.
- Server-side queue (R): "Owns the messages a user queued while a session was busy, and sends them the moment the session goes idle. The queue lives in the web server so a closed tab, a locked phone, or a dropped connection no longer strands it" ([message-queue/DOCUMENTATION.md](https://github.com/openchamber/openchamber/blob/main/packages/web/server/lib/message-queue/DOCUMENTATION.md)).
- Rate limits (R): "Limit failover": when a provider usage limit stops a session, switch to the provider's next stored account and move the session to a fallback model, both opt-in ([limit-failover/DOCUMENTATION.md](https://github.com/openchamber/openchamber/blob/main/packages/web/server/lib/limit-failover/DOCUMENTATION.md)); quota signals per provider ([quota/DOCUMENTATION.md](https://github.com/openchamber/openchamber/blob/main/packages/web/server/lib/quota/DOCUMENTATION.md)). Closest to our S8 among the 12, reactive rather than admission-time.
- Goals (R): "Session Goals" check the result after every turn and keep the agent working until done, blocked or limit ([README](https://github.com/openchamber/openchamber/blob/main/README.md)).
- Concurrency, locks: none of its own found.
- Adversarial (R): [#7332](https://github.com/openchamber/openchamber/issues/7332) managed server V8 OOM, restart, "chat interrupted" four times a day; [#6556](https://github.com/openchamber/openchamber/issues/6556) helper wrote 8.6GB in 85 minutes before Jetsam; [#5412](https://github.com/openchamber/openchamber/issues/5412) memory management.
- Modules: control panel for OpenCode, M5 rate-limit idea. Copy: server-owned prompt queue, limit failover (account switch, fallback model).

### Emdash (Classic)

- Process model (R): "The desktop app coordinates; workspace hosts execute", hosts are the local machine or SSH remotes ([CONTEXT.md](https://github.com/generalaction/emdash/blob/main/CONTEXT.md)); deps `node-pty`, `ssh2`, `better-sqlite3` ([package.json](https://github.com/generalaction/emdash/blob/main/package.json)); ACP conversations with "ACP Conversation command" ids that are idempotent per request (CONTEXT.md). Lifecycle hooks in agent configs track status and enable resume ([README](https://github.com/generalaction/emdash/blob/main/README.md)).
- Durability (R): "Queued Prompt payload: the Host-durable content snapshot that lets an accepted, undispatched Prompt attempt survive owner restart. It exists only before Provider dispatch"; "Session generation: the monotonically increasing fence for one Conversation's live Session incarnation"; pooled provider connections with their own generation fence; in-memory workspace runtime state is "ephemeral by design, absent after a daemon restart" ([CONTEXT.md](https://github.com/generalaction/emdash/blob/main/CONTEXT.md)).
- Multi-device (R): "host-authoritative" inventory, desktop registry converges toward it, tombstone-and-reconcile deletion ([ADR 0001](https://github.com/generalaction/emdash/blob/main/docs/adr/0001-host-authoritative-workspaces.md), [ADR 0006](https://github.com/generalaction/emdash/blob/main/docs/adr/0006-tombstone-and-reconcile-deletion.md)); one supervisor per host connection because SSH, Wire client and handshake can all look alive after sleep while requests no longer arrive ([ADR 0008](https://github.com/generalaction/emdash/blob/main/docs/adr/0008-host-connection-supervisor.md)); cancellation "is best-effort across planes" ([ADR 0004](https://github.com/generalaction/emdash/blob/main/docs/adr/0004-cancellation-is-best-effort-across-planes.md)).
- Concurrency, shared context: unknown.
- Adversarial (R): [#3426](https://github.com/generalaction/emdash/issues/3426) remote terminal input lags on high-RTT hosts; [#3437](https://github.com/generalaction/emdash/issues/3437) one provider lookup failure drops healthy remotes.
- Modules: M1 design reference (host-authoritative, per-host supervisor), M2 partial. ## 5. Patterns worth copying

1. Finite runs, durable intent (Paperclip, R): never keep a harness alive between turns by default; write the continuation as a row (`same_agent`, `retry`, `delegated_issue`, `response_wake`, `monitor`) and start a new run when it is eligible. Maps to our parked state and gives await types a schema.
2. Lazy hydration plus idle eviction that keeps the record (OpenHands agent server, Paseo, Orchestrator, R): three independent projects converged on "release the process after idle, keep the record, resume on next prompt". Orchestrator's eligibility table is the rule set to copy: never park while waiting for input, during an unconfirmed turn, during a controller transition, or while a viewer lease is held.
3. Detached per-session host (Orchestrator for ACP, Paradev for PTYs, R): put each live ACP connection in a small detached process that survives orchestrator restarts and replays acknowledged prompts, and let the orchestrator adopt it from a manifest. This turns G4 from a hope into a property. The cost is orphans (AO [#5948](https://github.com/OrchestratorInc/agent-orchestrator/issues/5948)), so pair it with a reaper keyed on session terminal state.
4. File lease with generation fence and crash detection (OpenHands `owner_lease.json`, R): TTL 45s, generation counter, owner host, pid and process start time, takeover flag. Fits M5 and M3 with no server. Emdash's session generation and QM's run claim are the same fence in other stores.
5. Per-key serialization in the claim (Multica, R): a task is claimable only if no other task for the same (issue, agent) is dispatched or running. This is our per-repo soft cap expressed as a claim predicate.
6. Lanes, one-turn-per-session mailbox, aging priority (OpenClaw, R): a session mailbox admits one turn per physical session before global capacity; lanes and capacity groups carry separate caps; priority gets a bounded head start then ages. Directly answers S2 and S9.
7. Message semantics for a busy session (OpenClaw, Paseo, R): `queue` (default, coalesced after a quiet window), `steer`, `interrupt`, and Stop holds queued messages instead of dropping them. Use this vocabulary for M5 `signal`.
8. Host-authoritative inventory with a per-host connection supervisor (Emdash, R): the device is authoritative, the hub converges, and connection readiness is invalidated after sleep instead of trusted from cache. Same conclusion as our Assessment 2, with a concrete failure mode to test (laptop sleep).
9. Pre-dispatch durable prompt snapshot and command ids (Emdash, QM, R): persist accepted prompts until provider dispatch, give every command an id so retries return the same result, and ack completions only after the parent's inbox write. Fixes the class of bugs CloudCLI has ([#1270](https://github.com/siteboon/claudecodeui/issues/1270)) and Paseo admits ("can lose or repeat a continuation").
10. Manifest-driven TUI state detection with `explain` (Herdr, R): regex rules per agent over screen regions, updatable without restart, with a command that shows which rule fired. This is what our tmux fallback needs to know "blocked vs idle" without ACP.
11. Limit failover (OpenChamber, R): on a provider usage limit, switch account or fall back to another model. None of the 12 throttles admission by quota; Paperclip's monthly budget check is the only admission-time spend control (R). S8 stays our glue, as the framing doc already says.
12. Derived status (Orchestrator, R): store facts (`activity_state`, `hibernated_at`, generation, PR facts), compute display status at read time. Keeps M3 small and avoids status drift bugs like Paperclip [#14752](https://github.com/paperclipai/paperclip/issues/14752).

What the set gets wrong, collectively:
- Memory: four of the twelve have open OOM or unbounded-RSS issues on the orchestrator itself (OpenClaw, Paseo, OpenChamber, Paperclip). Unbounded in-memory timelines are the common cause. Our M3 should keep transcripts on disk and only pointers in memory.
- Reboot: none of the desktop-first tools (Paradev, Herdr, Paseo, Orchestrator, CloudCLI) resumes all sessions after a machine reboot by default; Paseo's is opt-in and best effort, Paradev's is a feature request.
- Caps: caps are counts (10, 20, 6 per agent, lanes); none uses memory or presence (S14), and OpenHands rejects instead of queueing.
- Subagents: OpenHands and Paperclip both lose subagent or continuation state across restarts (issues cited above). Delegation state needs the same durability as the parent session.

## 6. Unknowns

- Idle and live RSS for every orchestrator except Herdr; no project publishes a number in the docs read.
- Concurrency caps for Paradev, CloudCLI and Emdash, and whether Paseo or Orchestrator cap sessions anywhere outside the grepped server sources.
- CloudCLI behavior for an in-flight run on server restart (not documented).
- OpenClaw node-hosted runs when the Gateway is unreachable.
- Herdr per-pane overhead and whether its socket API is stable enough to wrap.
